## What surprised me / patterns

- A known-broken pattern (Codex `--permission edit`) was re-attempted without checking `past-mistakes.md` first, burning a full dispatch-and-wait cycle for a failure that was already fully documented that same day.
- The manual-transcription instinct for binary email attachments is a repeatable trap: when no dedicated tool exists for binary content, the first move should be asking the human to fetch it, not attempting a workaround that looks technically clever but is unreliable and expensive.
- Vercel's Root Directory setting interacting with CLI invocation location is a sharp edge worth remembering (`prototype/prototype` doubling).

## Lessons learned

Both written to `past-mistakes.md`:
1. Don't hand-reconstruct binary attachment content from a Gmail RAW MIME dump — ask the user to download it.
2. Check `past-mistakes.md` before re-dispatching a pattern that failed earlier the same session/day.
