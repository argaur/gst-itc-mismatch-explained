## Existing workflow represented in the wireframe

The current-flow reconstruction is based on published GST Portal/government guidance checked on 2026-08-26. It deliberately avoids government logos, live portal access, and a claim of pixel-perfect replication. The navigation and process are documented; the visual styling and case data are reconstructed.

The six stages shown are:

1. **Receive and log in** — recognise a pending Return Compliance alert.
2. **Navigate** — use `Services → Returns → Return Compliance`, or the dashboard shortcut.
3. **Find the reference** — open the ITC Mismatch (DRC-01C) tile, filter/search, and select the pending reference number.
4. **Read Part A** — see the aggregate GSTR-3B-versus-GSTR-2B difference and the requirement to respond through Part B.
5. **Reconcile outside the portal** — compare the GSTR-3B summary, GSTR-2B extracts, and purchase/claim workpaper to discover the invoice-level cause. This is the core problem illustrated by the comparison: the portal provides the aggregate flag and official reply channel but does not perform the taxpayer's invoice-level diagnosis.
6. **File Part B** — provide a DRC-03 ARN, a selected reason plus explanation, or both; complete declaration/signatory/place fields; save; download/check the draft; proceed; file with EVC or DSC; verify OTP; and reach Completed status.

The page also states the documented consequence: if DRC-01C Part B is not filed, a subsequent GSTR-1/IFF filing can be blocked.

## Proposed workflow represented in the wireframe

The four stages remain:

1. **Understand the notice** — show the ₹21,600 difference in plain language before tax jargon.
2. **Trace the evidence** — deterministic reconciliation links the total to visible source rows.
3. **Explain the findings** — preview a constrained, structured OpenAI explanation grounded only in validated findings. The wireframe simulates loading and output; it does not itself call a model.
4. **Prepare for review** — produce a print-friendly professional-review brief with arithmetic, evidence IDs, a short mock Part B draft, checklist, limitations, and an explicit `Nothing has been submitted to GSTN` statement.

The intended real prototype boundary remains unchanged: deterministic code owns matching, classification, and arithmetic; a real server-side OpenAI call owns grounded explanation and constrained drafting; qualified human review remains required.
